# 雲端認證資料同步規格書

**文件版本**：v1.0  
**建立日期**：2026-10-19  
**適用專案**：國泰 Apptio（FinOps）7+1 環境整合

---

## 一、背景與現況說明

1. **專案進度與架構調整**：國泰 Apptio（FinOps）專案目前已進入尾聲階段。原規劃為單一 SaaS 環境，後因客戶資安與各子公司政策需求，拆分為 7 個獨立子公司環境 + 1 個 FCoE（7+1）。

2. **面臨之挑戰**：因環境拆分，FCoE（+1 環境）缺乏 AWS/GCP 帳號資料及相關設定，無法直接檢視各子公司的整體帳務，導致難以達成集團層級統一檢視與管理的目標。

3. **需求與解法**：Apptio 原生尚不支援多環境間 AWS/GCP 帳號資料自動同步，但可透過撰寫腳本（Script）呼叫 Cloudability API v3 實現 AWS/GCP 帳號資料同步至 FCoE。需協請康和夥伴協助撰寫同步程式。

---

## 二、目標與範圍

### 2.1 同步目標

將 7 個子公司 Cloudability 環境中已設定的 AWS / GCP Vendor Accounts（雲端帳號認證資料），自動同步至 FCoE 環境，使 FCoE 具備集團層級的帳務彙整與統一管理能力。

### 2.2 同步範圍

| 項目     | 說明                                         |
| -------- | -------------------------------------------- |
| 來源環境 | 7 個子公司 Cloudability 環境（各自獨立 Org） |
| 目標環境 | FCoE Cloudability 環境（+1）                 |
| 同步對象 | AWS Vendor Accounts、GCP Vendor Accounts     |
| 同步方向 | 單向（子公司 → FCoE）                        |
| 觸發方式 | 排程執行（建議每日一次）或手動觸發           |

### 2.3 不在範圍內

- 子公司環境之間的帳號互相同步
- 費用資料（Cost Data）的跨環境同步
- Business Dimensions / Tag 對應規則的同步
- 使用者帳號（User）的同步

## 三、系統架構

```
┌─────────────────────────────────────────────────────────────┐
│                    同步腳本（Sync Script）                   │
│                      執行環境：排程主機                       │
└────────────────┬──────────────────────┬─────────────────────┘
                 │ 讀取（READ）          │ 寫入（WRITE）
                 ▼                      ▼
  ┌──────────────────────┐   ┌──────────────────────┐
  │  子公司環境 × 7       │   │   FCoE 環境 × 1      │
  │  Cloudability API v3 │   │  Cloudability API v3 │
  │  GET vendor_accounts │   │  POST vendor_accounts│
  └──────────────────────┘   └──────────────────────┘
```

## 四、Cloudability API v3 規格說明

### 4.1 認證方式

Cloudability API v3 使用 **HTTP Basic Authentication**：

- **Username**：各環境的 API Key
- **Password**：留空（空字串）

```
Authorization: Basic BASE64(api_key:)
```

各環境需分別持有對應的 API Key，共需 8 組（7 個子公司 + 1 個 FCoE）。

### 4.2 Base URL

```
https://api.cloudability.com/v3/
```

### 4.3 讀取子公司 Vendor Accounts

**端點**

```
GET curl 'https://api.cloudability.com/v3/vendors/AWS/accounts?viewId=0' -u ‘[auth_token]:’
```

**Query Parameters**

| 參數     | 型別   | 必填 | 說明                                                                                                                                                                           |
| -------- | ------ | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `viewID` | string | 否   | To ensure the API returns all accounts with these credentials requests, add viewId=0 as a URL parameter. This will ensure any default view on your user account isn't applied. |

### 4.4 檢查 FCoE 環境是否已存在 Vendor Accounts

**端點**

```
GET https://api.cloudability.com/v3/vendors/AWS/accounts/[vendorAccountId]
```

### 4.5 在 FCoE 環境新增 Vendor Account

若 FCoE 環境不存在相同 `vendor_account_id`，則執行新增（POST）：

**端點**

```
POST https://api.cloudability.com/v3/vendors/AWS/accounts/
```

**Request Headers**

```
Content-Type: application/json
```

**Request Body（AWS範例）**

```json

  "type": "aws_role",
```

### 4.6 更新 FCoE 環境既有 Vendor Account

若 FCoE 環境已存在相同 `vendor_account_id`，則執行更新（PUT）：

**端點**

```
PUT https://api.cloudability.com/v3/vendors/AWS/accounts/[vendorAccountId]
```

**Request Body**：同 POST，帶入需更新的欄位即可。

## 五、同步邏輯流程

```
開始
 │
 ├─ 1. 逐一呼叫 7 個子公司環境 GET /vendor_accounts
 │       ↓ 收集所有 AWS + GCP 帳號清單
 │
 ├─ 2. 呼叫 FCoE 環境 GET /vendor_accounts
 │       ↓ 取得 FCoE 現有帳號清單
 │
 ├─ 3. 比對差異（以 vendor_account_id + vendor 為唯一鍵）
 │       ├─ 子公司有、FCoE 無 → POST（新增）
 │       ├─ 子公司有、FCoE 有 → 比對 credentials 是否異動 → 有異動則 PUT（更新）
 │
 ├─ 4. 記錄同步結果至 Log
 │
結束
```

## 六、設定檔規格

同步腳本透過設定檔（`config.yaml` 或環境變數）管理各環境 API Key，範例如下：

```yaml
# config.yaml
environments:
  subsidiaries:
    - name: "子公司A"
      api_key: "${SUBSIDIARY_A_API_KEY}"
      enabled: true   # false 時跳過此子公司的同步作業
    - name: "子公司B"
      api_key: "${SUBSIDIARY_B_API_KEY}"
      enabled: true
    - name: "子公司C"
      api_key: "${SUBSIDIARY_C_API_KEY}"
      enabled: true
    - name: "子公司D"
      api_key: "${SUBSIDIARY_D_API_KEY}"
      enabled: true
    - name: "子公司E"
      api_key: "${SUBSIDIARY_E_API_KEY}"
      enabled: true
    - name: "子公司F"
      api_key: "${SUBSIDIARY_F_API_KEY}"
      enabled: true
    - name: "子公司G"
      api_key: "${SUBSIDIARY_G_API_KEY}"
      enabled: true
  fcoe:
    name: "FCoE"
    api_key: "${FCOE_API_KEY}"

sync:
  vendors:
    - amazon
    - google
  enable_delete: false # 是否啟用刪除同步（預設關閉）
  log_path: "./logs/sync.log"
```

> **子公司啟用控制**：各子公司項目的 `enabled` 屬性控制是否納入同步作業。設為 `false` 時，同步程式將完全跳過該子公司，不進行任何 API 呼叫。省略 `enabled` 欄位時，預設視為 `true`。

> **資安注意事項**：API Key 不得明文寫入設定檔，須以環境變數或密鑰管理工具（如 HashiCorp Vault、AWS Secrets Manager）注入。

## 七、錯誤處理

| HTTP 狀態碼             | 說明                           | 處理方式                          |
| ----------------------- | ------------------------------ | --------------------------------- |
| `200 OK`                | 讀取成功                       | 繼續處理                          |
| `201 Created`           | 新增成功                       | 記錄 Log                          |
| `400 Bad Request`       | 請求格式錯誤                   | 記錄錯誤 Log，跳過該帳號          |
| `401 Unauthorized`      | API Key 無效                   | 終止該環境同步，發出告警          |
| `404 Not Found`         | 帳號 ID 不存在（PATCH/DELETE） | 改以 POST 新增                    |
| `409 Conflict`          | 帳號已存在                     | 改以 PATCH 更新                   |
| `429 Too Many Requests` | 超過 API Rate Limit            | 等待後重試（Exponential Backoff） |
| `5xx Server Error`      | Cloudability 服務異常          | 記錄 Log，等待重試                |

## 八、排程與執行建議

| 項目         | 建議值                                  |
| ------------ | --------------------------------------- |
| 執行頻率     | 每日一次（建議非尖峰時段，如凌晨 2:00） |
| 執行方式     | Cron Job / 工作排程器（Task Scheduler） |
| 重試機制     | 失敗後最多重試 3 次，間隔 60 秒         |
| Log 保留期限 | 30 天                                   |
| 告警通知     | 同步失敗時發送 Email 或 Slack 通知      |

## 十、附錄：Cloudability API v3 參考端點

| 方法   | 端點                                                      | 說明                         |
| ------ | --------------------------------------------------------- | ---------------------------- |
| GET    | `/v3/vendors/AWS/accounts`                                | 取得所有 Vendor Accounts     |
| GET    | `/v3/vendors/AWS/accounts/[vendorAccountId]`              | 取得單一 Vendor Account      |
